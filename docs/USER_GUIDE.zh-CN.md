# AI Context Hub 中文操作手册

[English guide](USER_GUIDE.md)

## 1. 安装与启动

安装 Node.js 20.19+ 或 22.12+ 和 npm 11.11.0+，然后执行：

```sh
git clone https://github.com/mason2048/ai-context-hub.git
cd ai-context-hub
npm ci
npm run dev
```

打开 <http://127.0.0.1:43100>，保持终端运行。需要停止时，在该终端按 `Ctrl+C`，前端和 API 会一并退出。

验证本地生产构建：

```sh
npm run build
npm start
```

打开 <http://127.0.0.1:43101>；同样使用 `Ctrl+C` 停止。

## 2. 第一次扫描

1. 先保留页面预填的 `sample-project` 绝对路径；
2. 阅读页面显示的包含规则、硬排除项和扫描上限；
3. 点击“开始只读扫描”，等待完成；
4. 确认规则、Skill、知识、工具元数据和风险条目已出现；
5. 打开风险区域，检查示例中故意设置的命令冲突、重复、失效链接和已脱敏秘密。

扫描真实项目时，输入项目根目录的绝对路径。状态目录不能位于项目内部、项目上层或与项目发生其他重叠。工具不会跟随符号链接，也不会读取秘密文件、依赖目录、构建产物和安全硬排除目录。

## 3. 筛选与审核

可以组合使用文本搜索、类型、作用域、风险和来源筛选。打开条目后检查摘要、相对来源、定位、revision、作用域、敏感级别、标签和 Token 数。取消条目勾选只会将它排除在当前导出之外，不会修改源项目或删除快照。

## 4. 刷新与差异

打开已保存的项目后执行刷新。成功刷新会创建新的不可变快照，并显示新增、变化、移除和未变化条目。取消、失败、截断或超过上限的刷新不会替换最后一份完整快照。

## 5. Token 预算与导出

1. 打开“导出预览”；
2. 选择 Context Package JSON 或 `AGENTS.md`；
3. 输入最大 Token 预算；
4. 选择 `warn`、`block` 或 `auto-trim`；
5. JSON 可选启用 Ed25519 签名；
6. 重新生成预览，检查完整正文、精确 Token、包含项和省略项；
7. 审核完成后再下载。

`block` 会拒绝超预算导出；`auto-trim` 会按稳定优先级省略较低优先级条目并列出清单。任何选择或选项变化都会使旧预览失效。JSON 可能包含绝对来源 URI，向可信本机以外分享前应删除敏感元数据。

## 6. 导入 Context Package

1. 点击“导入 Context Package”；
2. 在浏览器中选择 JSON 文件；
3. 审核 schema、生产者、条目数量、敏感项、签名状态和警告；
4. 确认后创建本地导入快照。

导入器只读取用户选择的 JSON 文本，不请求包内 URL、不读取包内声明的路径、不执行正文，也不会把原始 JSON 复制进项目。无效 schema、重复 ID、明文秘密、无效签名和超限内容会直接阻断。

## 7. 备份与恢复

复制状态前先停止应用。默认状态目录：

- macOS：`~/Library/Application Support/AI Context Hub/v1`
- 其他系统：`~/.local/share/ai-context-hub/v1`

使用受访问控制的本地备份完整复制目录，包括 manifest、快照和签名材料。只在应用停止时恢复，并保留文件权限。不要把该目录提交到 GitHub。

临时体验可指定隔离目录：

```sh
CONTEXT_HUB_DATA_DIR=/absolute/private/context-hub-evaluation npm start
```

## 8. 重置或清理数据

产品没有静默重置命令。先停止应用，核对精确状态路径，按需备份，然后只把该状态目录移到系统废纸篓；不要删除宽泛的上层目录。重新启动后，会在第一次成功保存时创建新状态。废纸篓清空后无法恢复，但该操作不会修改任何扫描过的项目。

卸载源码时，停止服务后只删除克隆得到的 `ai-context-hub` 目录。npm 依赖与 `dist` 位于克隆目录中，产品状态位于上述独立位置。

## 9. 运行检查

```sh
npm test
npm run build
npm audit
```

测试依赖故意保留的 `sample-project/node_modules/ignored-rule/AGENTS.md` 夹具。干净克隆中它必须存在，但扫描结果中不能出现。

## 10. 故障处理

- **Node 版本不支持：**使用 Node 20.19+ 或 22.12+，不要使用 Node 21；
- **端口被占用：**停止占用 43100 或 43101 的进程再重启；源码预览版有意固定这两个端口；
- **路径被拒绝：**输入真实绝对目录，并确保 `CONTEXT_HUB_DATA_DIR` 在扫描树之外；
- **扫描只得到部分结果：**缩小范围或清除不必要的生成文件后刷新；部分结果不会推进 latest；
- **导出被阻止：**提高预算、切换为 `warn`、使用 `auto-trim`，或审核后取消部分条目；
- **导入失败：**使用 `context-package.schema.json` 校验，移除明文凭据，不要绕过签名或大小门禁；
- **出现意外秘密告警：**先按真实凭据处理并在必要时轮换；规则检测也可能误报；
- **页面无法访问 API：**使用页面显示的回环地址，不要通过不可信来源代理本机服务。

## 支持边界

这是源码预览版，没有托管后端、账户恢复、生产 SLA，也不保证其他 AI 工具一定采用导出内容。可复现且不含敏感信息的普通问题请创建 GitHub Issue；安全问题请使用 Private Vulnerability Reporting。
